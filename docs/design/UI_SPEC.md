Источник: [принятый концепт](feed-concept.png), просмотрен через view_image перед реализацией. Область работ: только web/ и этот документ. API: [контракт](../API_CONTRACT.md), [требования](../IMPLEMENTATION_PLAN.md).

## Визуальная система

Концепт 1505 × 1045: белое полотно, открытая лента без карточек, шапка с нижней границей, текстовый SweetNet слева, навигация посередине, выход справа. Лента уже шапки и центрирована. Бирюзовая основная кнопка, подчёркнутая активная вкладка, тонкие серые разделители статей. Аватаров, теней и декоративных иллюстраций нет.

## Разрешённый текст и композиция

Шапка: SweetNet, Лента, Профиль, Участники, Приглашения, Выйти. Участники и Приглашения видны только owner. Лента: «Наш круг», «Моменты, которыми хочется поделиться.», «Новый пост», «Только для участников круга». У статьи реальные имя автора, @username, локальная дата, текст и фото; «Изменить» — автору, «Удалить» — автору или владельцу. Дата ведёт к отдельному посту. Плюс кнопки — небольшая линейная SVG-иконка.

## Страницы и необходимые расширения концепта

- /login: логин, пароль, ошибка входа, пояснение о приглашении и восстановлении через владельца.
- /join#token=…: токен забирается в память до запуска роутера, fragment удаляется через replaceState. Username, имя, пароль; явное сообщение «Публикации доступны всем участникам этого закрытого круга», включая историю до вступления. Нет сохранения в browser storage.
- /: реальная лента по 20, загрузка, ошибка с повтором, пустое состояние, «Показать ещё»; нет seed-данных.
- /posts/new: текст 0–5000 Unicode code points, 0–4 JPEG/PNG до 10 MiB каждый, предпросмотры с удалением, текст или фото обязательны.
- /posts/:id и /posts/:id/edit: просмотр, изменение только текста, подтверждение удаления.
- /profile: имя, неизменяемый username, смена пароля с отзывом всех сессий.
- /admin/users: строки участников, статус, отключение с подтверждением, повторное включение.
- /admin/invites: создание, одноразово показанная ссылка и копирование, сроки, статусы, отзыв с подтверждением.
- Неизвестный путь: понятное сообщение и возврат в ленту.

Повторяемые компоненты: PageHeading, Button (primary/secondary/text/danger), Field, ErrorNotice, Loading, EmptyState, ConfirmDialog, PostArticle, ProtectedImage. Формы и административные строки продолжают открытый контейнер концепта; без сеток декоративных карточек. Диалог — семантический dialog с клавиатурным закрытием и восстановлением фокуса.

## Явные допущения и отклонения

1. Концепт содержит демонстрационные записи Михаила и Анны и озеро. Их нет в продукте: посты и фотографии приходят только из API; пустая БД показывает пустую ленту.
2. Размеры концепта перенесены в CSS по пропорциям: ширина ленты около 76% ширины шапки, с верхними ограничениями 840/1100px как реализационное допущение. Это намеренно чуть уже исходных 880/1120px.
3. Шрифт концепта не поставлен отдельным файлом; используется близкий системный sans-serif. Белый фон и отсутствие теней сохранены.
4. Регистрация, профиль, редактор, ошибки, пустое состояние и admin не нарисованы отдельно: необходимые по заданию формы получают общие токены, поля, кнопки и разделители. Их функциональные подписи являются разрешённым расширением исходного текста.
5. На 360px шапка складывается в две строки с прокручиваемой навигацией, заголовок и основное действие располагаются вертикально; нет обрезки основного контента.
6. Реальные фотографии сохраняют собственные пропорции (object-fit: contain), не обрезаются под панораму из демонстрационного поста. До четырёх изображений идут последовательно.
7. Ошибка выхода не выдаётся за успешный отзыв: пользователь остаётся в интерфейсе с явным сообщением и повторной кнопкой выхода. При 401 приватное дерево размонтируется, запросы отменяются, blob URL отзываются.
8. Нет localStorage/sessionStorage, аналитики, внешних шрифтов и production mock-данных. Проверка типов, размера и количества файлов в UI дополняет серверную проверку реального формата и пикселей.

## Проверки

Проверено 2026-09-12: typecheck, lint, production build; 4 Playwright-сценария с реальными Go/PostgreSQL. Страница входа также проверена во встроенном браузере Codex через accessibility tree. Повторяемые сценарии двух изолированных браузерных контекстов и клавиатуры находятся в `tests/specs/`.

Концепт и итоговые скриншоты просмотрены через `view_image` в одной проверке: [desktop 1505×1045](feed-desktop.png), [mobile 360×800](feed-mobile.png). Первые тесты использовали однопиксельный PNG; для содержательной проверки масштаба фото заменён на [синтетическую фотографию](../../tests/fixtures/lake.png), созданную встроенным Imagegen. В production тестовых записей нет.

Описание генерации тестового фото: photorealistic wide northern lake, pine forest, rocks and pine trunk on the left, blue sky, late summer daylight; no people, text, borders or graphics. Файл только в test fixtures.
