# SweetNet

Закрытая социальная сеть для меня и друзей: публикации доступны только участникам, регистрация — по приглашению владельца.

Сейчас в репозитории подготовлено задание для разработки. Приложение ещё не реализовано.

## Первый релиз

| Часть | Выбранное решение |
| --- | --- |
| p1 — база данных | PostgreSQL |
| p2 — backend | Go + chi + pgx |
| p3 — API | REST/JSON + OpenAPI; реализуется внутри Go-backend |
| p4 — web-приложение | React + TypeScript + Vite |

Один закрытый круг, приглашения, вход и выход, общая лента, текст и фотографии, редактирование своих постов, профиль и управление участниками. Все участники видят все посты круга. Комментарии, лайки и чат отложены до следующих версий.

## Как начать разработку с Codex

Открой папку `SweetNet` в Codex и отправь:

```text
Прочитай AGENTS.md и docs/IMPLEMENTATION_PLAN.md и реализуй первый релиз SweetNet.
Начни с проверки репозитория, затем выполняй этапы 0–6 с проверками.
Веди docs/PROGRESS.md и продолжай после каждого этапа до выполнения критериев готовности.
Рутинные решения принимай самостоятельно в рамках задания.
```

`AGENTS.md` задаёт постоянные инструкции для Codex; подробное техническое задание находится в [плане реализации](docs/IMPLEMENTATION_PLAN.md). Наличие файла само по себе не запускает работу: нужно отправить сообщение выше.

Если реализация прервалась, отправь:

```text
Продолжи реализацию SweetNet по AGENTS.md, docs/IMPLEMENTATION_PLAN.md и docs/PROGRESS.md.
Проверь фактическое состояние кода и начни с первого незавершённого этапа.
```

## Путь разработки

1. Подготовить каркас и Docker Compose.
2. Создать PostgreSQL-схему и миграции.
3. Реализовать Go-backend и API: приглашения, аккаунты, права доступа.
4. Добавить посты, фотографии и закрытую ленту.
5. Подключить React-интерфейс к реальному API.
6. Проверить работу двух пользователей, приватность и сохранение данных.
7. Подготовить инструкции запуска, HTTPS, резервного копирования и восстановления.

После реализации Codex должен дополнить этот README проверенными командами запуска. Публикация на внешнем сервере — отдельный шаг после локальной проверки и выбора хостинга.
