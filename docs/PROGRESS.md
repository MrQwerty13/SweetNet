Дата проверки: 2026-09-12. Итоговая ветка: `codex/04-release`.
Исходный `main`: `b39b5a4`. Карта веток и файлов: [REVIEW.md](REVIEW.md).

не заявляется: Docker Engine недоступен, контейнерный прогон и реальный HTTPS
ещё не выполнены. Это ограничение среды, а не отметка об успешном прохождении.

## Выполненные команды

Все команды запускались на текущем исходном коде, а не только на предыдущей сборке.
Go 1.26.4, Node 26.0.0, PostgreSQL 17.11, macOS arm64 Apple M3.

- `make check` с отдельной `TEST_DATABASE_URL`: **exit 0**. Включает форматирование,
  `go vet`, unit-тесты, `go test -race -count=1 ./...` с PostgreSQL, frontend
  typecheck/build/lint, OpenAPI, maintenance, browser, backup rehearsal.
- `node tests/run-e2e.mjs`: **4 passed**, 2 независимых контекста и гость. Playwright
  запускал установленный Google Chrome через `E2E_CHROME_PATH`; встроенный браузер
  Codex отдельно подтвердил корректную страницу входа и отсутствие ложного сообщения о сессии.
- `python3 -m unittest discover -s deploy/tests -v`: **17 passed**; сбои копирования,
  перезапуск через trap, конфликты обслуживания, повреждённые архивы и новый target.
- `node tests/validate-openapi.mjs`: **OpenAPI 3.1.0, 14 paths validated**;
  браузерные тесты дополнительно валидируют реальные JSON-ответы схемами.
- `node tests/verify-backup.mjs`: **PASS**. Две отдельные новые базы, реальный
  pg_dump/pg_restore, tar/checksums, перезапуск, аккаунты, точные байты фото,
  использованное приглашение и проверки прав после восстановления.
- `npm audit` в `web` и `tests`: **0 vulnerabilities** на момент проверки.
- `docker manifest inspect`: теги Go/Node/PostgreSQL/Caddy найдены; это проверка
  registry, не сборка или запуск контейнеров.
- Argon2id benchmark: около **25.7 ms/hash**, 3 измерения, Apple M3. Для VPS нужен свой замер.

Секреты тестовых аккаунтов генерируются при запуске, не печатаются. Тесты используют
схемы с UUID и отдельные временные каталоги; backup rehearsal создаёт и удаляет
только свои новые базы. Пользовательские данные и volumes не удалялись.

## Критерии первого релиза

| Критерий | Проверка / состояние |
| --- | --- |
| Чистая сборка | Финальная проверка из отдельной копии выполняется перед передачей |
| Перезапуск сохраняет данные | Подтверждён native rehearsal; Docker persistence ожидает контейнерного прогона |
| Владелец без публичного bootstrap/стандартного пароля | CLI + повторный bootstrap + уникальный индекс |
| Одноразовые, просроченные и отозванные приглашения | Go integration; параллельная регистрация даёт ровно одного участника |
| A публикует, B видит текст/фото | Реальный Playwright-сценарий |
| Гость не получает профиль, посты и изображения | Go integration + браузер/API + восстановленная копия |
| Только автор редактирует; owner может удалить | Go integration + Playwright, подмена полей отвергается |
| Отключение закрывает доступ, старые сессии не оживают | Go integration + mobile browser |
| Выход/смена/сброс пароля и срок сессии | Go integration + UI смены пароля + CLI reset |
| Origin и rate limit | Go integration; Secure/HttpOnly/SameSite проверены; password workers ограничены |

| Удалённое фото недоступно, нет кэша после выхода | Go integration + браузерный возврат назад |
| Пагинация и ошибки форм | Go integration + Playwright с имитацией 503 только внутри теста |

| Контракт, миграции, проверки и журнал | OpenAPI + Makefile + CI + этот файл |
| Восстановление копии с постами и фото | Подтверждено PostgreSQL/native; Docker restore пока не подтверждён |
| Приватные данные не в git/логах | .env/.local/uploads/backup исключены, логи не печатают тела запросов/секреты |

## Исправления, найденные проверками

1. Браузерный тест воспроизвёл старый текст после редактирования: разные ключи
   страниц просмотра/редактора заставляют заново получить актуальный пост.
2. Первый визит больше не сообщает об истечении ещё не существовавшей сессии.
3. Интеграционный тест воспроизвёл очистку текста через `{}`: PATCH теперь требует
   явную строку body; null и отсутствие поля возвращают 400.
4. Неопределённый результат COMMIT сохраняет файлы для безопасной offline-сверки;
   тестирует выбор поведения по ошибке. Физический обрыв сети во время COMMIT
   не инъецировался, поэтому такой fault-injection отдельно не заявляется.
5. Ограничены одновременно выполняемые операции Argon2 и размер ключей limiter;
   очистка сессий не блокирует несвязанные аккаунты.
6. Обновлены test-only ajv/yaml; frontend отформатирован для ревью.
